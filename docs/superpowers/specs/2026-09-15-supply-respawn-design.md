# 补给延迟重生 — 设计

2026-09-15

## 问题

每波开局固定生成 7 个补给（`Item.values()` 各一），被拾取后从地图上**永久移除**，本局内不再出现
（`TankGameModel.collect()`）。补给是一次性消耗品，一局打到后期地图上越来越空。

敌人死亡有 28% 概率掉落额外补给（`damage()`），但那是击杀奖励，不解决「地图逐渐空掉」的问题。

## 目标

让开局那 7 个补给成为**可循环的槽位**：被拿走一段时间后在别处回来，使整局内补给密度保持稳定，
同时不引入无限资源。

## 规则

| # | 规则 |
| --- | --- |
| 1 | 开局 7 个补给各自是一个独立槽位 |
| 2 | 槽位被拾取消耗后进入 **10 秒**倒计时 |
| 3 | 倒计时结束，在另一个随机空闲格子重生**同类型**补给；**排除刚被消耗的那个格子** |
| 4 | 敌人掉落的补给**不参与循环**，捡完即消失 |
| 5 | 多人模式（MULTI / COOP）下 **TURRET 槽位不重生** |
| 6 | 背包满时拾取 TURRET 失败 → 补给留在地上、槽位不消耗（保留现有 `applyItem` 返回 false 的行为） |

规则 5 的推论：多人模式中 TURRET 被取走一次后该槽位永久消失，循环剩 6 个槽位。
这里是「跳过」而不是「重生时换成其它道具」。

规则 4 的理由：敌人掉落由每次击杀新增，若也参与循环，场上补给数会随击杀数单调增长
（100 次击杀约多出 28 个常驻补给）。

## 常量

`Rules.ITEM_RESPAWN_MS = 10000` — 与 `TERRAIN_REFRESH_MS` 同频，让玩家形成统一的
「地图每 10 秒变一次」预期，不必记两套节奏。

## 技术方案

**全部改动在 `TankGameModel` 内部，协议与客户端零改动。**

- 种子补给与敌人掉落拆成两个内部列表，`snapshot()` 合并后照常发出一个 `List<PickupView>`
- `Snapshot` 结构不变 → `Protocol.VERSION` 不用升（保持 4）→ `RemoteGameModel`
  （本就直接透传 `to.pickups()`，不做插值）、`BattleRenderer`、`MultiplayerWindow` 一行不改
- 重生位置复用 `refreshTerrain()` 已有的空闲格校验（避开地形区、坦克、炮塔、传送门、其它补给）
- 倒计时按 `tick(8)` 递减，与现有 `intermissionMs` 同一套写法。因此**暂停 / 商店 / 部署 / 局间强化
  期间倒计时一并冻结**（`tick()` 在非 `RUNNING` 状态直接返回），与模型内其它计时器行为一致
- 槽位状态在 `initializeWave()` 重置

**放置安全性**：`freeCell()` 只检查 `used` 集合、不检查 `map.blocked()`。这里不需要为此加检查——
补给放在格子中心，墙是格子边界上 6px 的细线（`GridMap`），中心到最近墙边缘至少 37px，
而拾取判定半径只有 11px。

## 改动范围

- `Rules` — 新增 `ITEM_RESPAWN_MS`
- `TankGameModel` — 新增种子/掉落两个列表与倒计时表；`initializeWave()` 重置槽位；
  `collect()` 在消耗种子补给时排入倒计时；`tick()` 递减并触发重生；`snapshot()` 合并两个列表
- 其余文件不改

## 测试

`TankGameModel` 不导入 JavaFX，是纯模型层，可直接写单元测试：

- 拾取后 10 秒内不重生，10 秒后重生
- 重生位置不与坦克、炮塔、传送门、其它补给重叠
- 重生位置不等于刚被消耗的那个格子
- 暂停期间倒计时不推进，恢复后继续
- 重生道具类型与消耗的一致
- 敌人掉落被捡走后不再出现
- 多人模式下 TURRET 槽位取走后不再出现
- 背包满时拾取 TURRET 失败，槽位不倒计时、补给留在地上
- 新一波 / 重开时槽位与倒计时重置

## 不做的事

- 不改协议（`Protocol.VERSION` 保持 4），不改客户端与渲染层
- 不改敌人掉落概率（28%）
- 不做联机炮塔部署
- 不做联机卡顿优化（单独一轮推进）

## 已知问题（本次不处理）

`RemoteGameModel.deployTurret()` 恒返回 false，联机时永远不会进入 `DEPLOYING` 状态，
因此 TURRET 只增加 `turretStock` 却永远无法部署。规则 5 只是避免反复刷新一个用不了的槽位，
**没有修复这个功能缺失**。
